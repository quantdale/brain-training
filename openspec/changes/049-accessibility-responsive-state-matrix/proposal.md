# Campaign 049 — Accessibility, Responsive, System-UI & State-Matrix Hardening

## Objective

Exercise high-risk accessibility and responsive states beyond ordinary route
smoke coverage, then classify what is technically proven on the dedicated
Android release artifact.

## Scope

- light and dark themes;
- compact and large-font profiles;
- representative system settings, safe-area/tab overlap, scrolling, and
  reduced-motion boundaries;
- 44 dp interactive-target and accessible-name auditing;
- modal/overlay and data-management/system document/share boundaries;
- fresh, active, completed, empty, error, offline, search/filter, result,
  settings, and data states using existing deterministic fixtures and evidence;
- focused repair and rerun when a current user-visible defect is reproduced.

## Non-goals

No broad redesign, speculative refactor, medical claim, store-signing claim,
human TalkBack/usability claim, physical-device claim, or iOS/VoiceOver claim.
