# Campaign 036 — First-Run, Empty-State & Trust Experience

## Problem

A true clean-install Android observation shows that the core path is already
short and usable: Home presents Today's Workout and Start workout, Games has a
catalog, Progress and Game Detail are honest about having no sessions, and
Profile identifies the local player. Two first-run readings are less clear:
Home never states that training is local/offline, while Data Management says
the local database is "Empty" even though initialization has created the local
profile, today's workout instance, and quest rows. Rewards also presents the
included default cosmetics as 3/12 without explaining that the starter set is
intentional.

## Outcome

Make the observed clean-install state self-explanatory with compact copy and a
truthful local-store status. Preserve the existing first-play route, empty
Progress/Favorites/Game Detail states, seed data, persistence, and reward
ownership model.

## Non-goals

No account gate, network dependency, health questionnaire, forced reminder,
marketing carousel, large onboarding flow, schema/economy change, backup-format
change, or fabricated progress data.
