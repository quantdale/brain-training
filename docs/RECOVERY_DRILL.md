# Fresh-Session Recovery Drill

Proves that a fresh agent session can recover full development context from
committed repository state alone — no chat memory required. This is a Campaign
001 (WP-F) deliverable; run it at every meaningful milestone and after any
large context compaction.

## Procedure (exact steps)

Run these in order. The repository, code, and Git history outrank remembered
chat context.

1. **Orientation**
   ```bash
   git status
   git log --oneline -10
   git branch -a
   git remote -v
   ```
2. **Read governance and mission**
   - `AGENTS.md` (read completely; startup protocol + validation model)
   - `docs/PROJECT_CONSTITUTION.md` (locked product decisions)
   - `docs/MASTER_PLAN.md`, `docs/ARCHITECTURE.md`, `docs/ADRs` under `docs/adr/`
3. **Read the durable control plane** (`.agent/`)
   - `GOVERNANCE.json`, `GOAL.md`, `STATE.md`, `CURRENT_CAMPAIGN.md`
   - `KNOWN_ISSUES.md`, `VALIDATION.md`, `IMPACT_MAP.md`, `DECISIONS.md`
   - `modes/DAY.md` / `modes/NIGHT.md` (see [Execution modes](#execution-modes))
   - Active task packets under `.agent/tasks/` (e.g. `001-f-validation-ci.md`)
4. **Validate durable state**
   ```bash
   node scripts/validate-repo-state.mjs
   ```
   Expect `Repository state validation PASS`.
5. **Reconcile docs/state with code**: spot-check that `.agent/STATE.md` and
   `CURRENT_CAMPAIGN.md` match `git log` and the working tree; note drift.
6. **Check the app builds** (light validation, from `apps/mobile/`)
   ```bash
   npm run typecheck
   npm run test:ci
   ```
   Optionally `CI=1 npx expo export --platform web` for a bundle smoke.
7. **Pick the next action** from `CURRENT_CAMPAIGN.md` (or the active packet).
   Do not reopen locked decisions; if something looks contradictory, investigate
   the code first, then raise it only if it is a genuine blocker.
8. **Resume work**: if a previous wave left a documented checkpoint
   (`.agent/checkpoints/`), continue from there.

## Execution modes

The user selects the resource mode explicitly in the goal command; never infer
it from the clock.

- **Day mode** — `.agent/modes/DAY.md`: up to ~7 coder agents when safely
  partitioned, one emulator, restrained expensive build/test concurrency,
  light risk-based validation, no host-input interference.
- **Night mode** — `.agent/modes/NIGHT.md`: may use more CPU/RAM and heavier
  validation, still one emulator by default, never a full hardening campaign.

Both modes forbid host mouse/keyboard/focus automation.

## Dry-run evidence

Dry run performed by the WP-F coder agent on **2026-08-16** (repo at commit
`cc40262`, branch `main`, working tree clean) using exactly the procedure above:

| Step | Command | Result |
|---|---|---|
| 1 | `git status && git log --oneline -8 && git branch -a && git remote -v` | PASS — clean tree on `main`, ahead of `origin/main` by 1 commit |
| 2–3 | Read `AGENTS.md`, constitution, `.agent/*`, `modes/*`, `tasks/*` | PASS — context fully recoverable |
| 4 | `node scripts/validate-repo-state.mjs` | PASS — `Repository state validation PASS` |
| 6 | `npm run test:ci` (apps/mobile) | PASS — 1 suite, 1 test |
| 6 | `CI=1 npx expo export --platform web` | PASS — 3 bundles, 4 static routes, `Exported: dist` |
| 6 | `npm run typecheck` (apps/mobile) | FAIL — pre-existing `@types/jest` gap (see findings) |

Findings from the dry run (actionable, reported to the orchestrator):

- `apps/mobile` typecheck fails on `src/__tests__/infra.test.ts` because
  `@types/jest` is not installed (jest-expo brings `@jest/globals` but not the
  global `test`/`expect` type declarations). Runtime jest is green; the fix is
  orchestrator-owned (apps/mobile is a shared/forbidden surface for WP-F):
  add `@types/jest@~29.5.x` to `apps/mobile` devDependencies.
- `expo export --platform web` does **not** generate `.expo/types` (typed
  routes are generated by `expo start`); plain `tsc --noEmit` remains the CI
  typecheck (see `.github/workflows/app-ci.yml` comment).
- `expo-env.d.ts` is committed, so a fresh checkout typechecks without a local
  expo command, contrary to the ADR-0004 note "typecheck requires running an
  expo command first" — the ADR note is stale; CI reflects actual behavior.

Conclusion: a fresh agent can fully recover context and validation state from
the repository alone; the one failing check has a known one-line root cause
owned by the orchestrator.

## Swarm / convergence drill (wave 1)

Campaign 001 wave 1 is partitioned into six parallel coder packets, each with
an explicit objective, allowed/forbidden write surfaces, completion criteria,
cheap validation, and integration notes (format defined in
`.agent/tasks/README.md`):

| Packet | Objective | Primary write surface |
|---|---|---|
| `001-a-app-shell.md` | four-tab shell + design tokens | `apps/mobile/src/app/**`, `apps/mobile/src/components/**` |
| `001-b-persistence.md` | SQLite schema/migrations/profile | `apps/mobile/src/db/**`, `apps/mobile/src/persistence/**` |
| `001-c-game-sdk.md` | versioned Game SDK contracts | `apps/mobile/src/sdk/**` |
| `001-d-android-harness.md` | ADB/uiautomator runtime harness | `scripts/android/**` |
| `001-e-memory-game.md` | first Memory game | `apps/mobile/src/games/**` |
| `001-f-validation-ci.md` | CI/validation/recovery proof | `.github/workflows/**`, root `scripts/validate-*.mjs`, `docs/` |

**Shared-file ownership rule** (from `AGENTS.md` + `CURRENT_CAMPAIGN.md`):
the orchestrator alone merges shared hotspots — package manifests/lockfiles,
tsconfig, navigation registries, DB schema coordination, SDK contract
integration, generated registries/indexes. Packets report shared-file needs;
parallel agents never race on them.

**Convergence evidence (wave 0 — orchestrator-merged commit `cc40262`
"wave0: scaffold Expo SDK 57 app, test infra, stack ADR, campaign task
packets")**, which integrated: the full `apps/mobile` scaffold (`app.json`,
`tsconfig.json`, `package.json` + lockfile, `expo-env.d.ts`, `src/app` routes,
`src/components/**`, `src/constants/theme.ts`, `src/hooks/**`,
`src/__tests__/infra.test.ts`), `docs/adr/0004-campaign-001-stack-versions.md`,
the six wave-1 packets in `.agent/tasks/`, and `.agent/DECISIONS.md`.

**Convergence evidence (wave 1)**: IN PROGRESS — six packets are executing in
parallel; the orchestrator performs convergence edits (shared files) and
merges packet outputs onto `main`. On completion, the orchestrator appends
here which files were merged per packet and confirms: clean `main`, no
temporary branches/worktrees, validator + app checks green.

**Success contract**: merged wave leaves `main` buildable/startable, durable
state updated, no unresolved Critical/High defects, no abandoned temporary
branches.
