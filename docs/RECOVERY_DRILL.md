# Fresh-Session Recovery Drill

Proves that a fresh agent session can recover full development context from
committed repository state alone — no chat memory required. This is a Campaign
001 (WP-F) deliverable; run it at every meaningful milestone and after any
large context compaction.

## Procedure (exact steps)

Run these in order. The repository, code, and Git history outrank remembered
chat context.

1. **Orientation**
   ```bash
   git status
   git log --oneline -10
   git branch -a
   git remote -v
   ```
2. **Read governance and mission**
   - `AGENTS.md` (read completely; startup protocol + validation model)
   - `docs/PROJECT_CONSTITUTION.md` (locked product decisions)
   - `docs/MASTER_PLAN.md`, `docs/ARCHITECTURE.md`, `docs/ADRs` under `docs/adr/`
3. **Read the durable control plane** (`.agent/`)
   - `GOVERNANCE.json`, `GOAL.md`, `STATE.md`, `CURRENT_CAMPAIGN.md`
   - `KNOWN_ISSUES.md`, `VALIDATION.md`, `IMPACT_MAP.md`, `DECISIONS.md`
   - `modes/DAY.md` / `modes/NIGHT.md` (see [Execution modes](#execution-modes))
   - Active task packets under `.agent/tasks/` (e.g. `001-f-validation-ci.md`)
4. **Validate durable state**
   ```bash
   node scripts/validate-repo-state.mjs
   ```
   Expect `Repository state validation PASS`.
5. **Reconcile docs/state with code**: spot-check that `.agent/STATE.md` and
   `CURRENT_CAMPAIGN.md` match `git log` and the working tree; note drift.
6. **Check the app builds** (light validation, from `apps/mobile/`)
   ```bash
   npm run typecheck
   npm run test:ci
   ```
   Optionally `CI=1 npx expo export --platform web` for a bundle smoke.
7. **Pick the next action** from `CURRENT_CAMPAIGN.md` (or the active packet).
   Do not reopen locked decisions; if something looks contradictory, investigate
   the code first, then raise it only if it is a genuine blocker.
8. **Resume work**: if a previous wave left a documented checkpoint
   (`.agent/checkpoints/`), continue from there.

## Execution modes

The user selects the resource mode explicitly in the goal command; never infer
it from the clock.

- **Day mode** — `.agent/modes/DAY.md`: up to ~7 coder agents when safely
  partitioned, one emulator, restrained expensive build/test concurrency,
  light risk-based validation, no host-input interference.
- **Night mode** — `.agent/modes/NIGHT.md`: may use more CPU/RAM and heavier
  validation, still one emulator by default, never a full hardening campaign.

Both modes forbid host mouse/keyboard/focus automation.
