## Implementation summary

**B5 bottom-inset fix (`components/screen-shell.tsx`).** ScreenShell now
resolves bottom content padding per route kind: web keeps
`BottomTabInset + Spacing.four`; native tab routes keep `Spacing.four` (the
tab host absorbs the device inset); native pushed routes use
`max(deviceBottomInset, Spacing.four)` so interactive controls clear the
~34pt home-indicator zone on notched iPhones instead of sitting 24pt from the
edge. Route kind is detected via expo-router `useSegments().includes('(tabs)')`
(safe outside a router — falls back to `[]`, treated as pushed). Insets are
read defensively from `SafeAreaInsetsContext` (NOT `useSafeAreaInsets()`,
which throws without a provider) so isolated component harnesses keep working,
matching the provider-free tolerance of the native `SafeAreaView` already in
use. Public API unchanged (`{ children }`) — W13/W14 consumers unaffected.
Snapshot safety: in the jest environment expo-router supplies all-zero
initial metrics, so pushed-route padding stays 24pt and existing visual
baselines are byte-stable (reasoned from `expo-router/build/ExpoRoot.js`
INITIAL_METRICS + `react-native-safe-area-context@5.7` sources; not re-run).

**New platform module (`src/platform/`).**
- `capabilities.ts` — `platformKind`/`isNativePlatform`/`isWebPlatform`,
  `supportsHaptics()`, `supportsWebVibration()` (web-only DOM probe
  short-circuited behind the platform check, preserving the audit's "no DOM
  leakage" invariant).
- `layout.ts` — reactive dimension helpers on `useWindowDimensions` only
  (zero static `Dimensions.get`): `useWindowWidth`, `useIsCompactWidth`,
  `useIsWideWidth`, `useClampedContentWidth`.
- `keyboard.tsx` — first keyboard seam in the codebase:
  `getKeyboardAvoidingConfig()` (iOS `padding` + offset; Android relies on
  adjustResize → undefined behavior; web none) and `KeyboardAvoidingArea`
  (plain View passthrough on web).
- `touch.ts` — `MIN_TOUCH_TARGET_SIZE = 44` and `hitSlopToTouchTarget(size)`
  so small controls can meet the shell a11y 44pt contract via hitSlop.
- `index.ts` barrel; consumed as `@/platform`.

**Audio/haptics additive branches (`sdk/audio-haptics-real.ts`).** Added
`fireAndForgetHaptic()` which attaches `.catch` to the async expo-haptics
promises: the surrounding try/catch can never catch an ASYNC rejection
(UnavailabilityError on a backend-less platform), and bare `void promise`
would escalate to unhandled-rejection warnings. Fail-open semantics preserved;
no call values changed. `prepare()` keeps one unconditional
`setAudioModeAsync({ playsInSilentMode: true, interruptionMode: 'mixWithOthers' })`
call with per-platform semantics documented in comments (iOS mute-switch
override; Android ignores the key but honors interruptionMode; web stub is a
no-op) — deliberately NOT branched because `sdk/__tests__/audio-haptics.test.ts`
asserts the exact call and the stub makes branching pointless.

**tokens.ts (additive only).** Completed `BottomTabInset` with `default: 0`
(the `web: 64` key had already been applied by a concurrent worker when I
arrived — audit A2; ios/android values untouched). New keys:
`CompactLayoutMaxWidth = 480`, `MediumLayoutMaxWidth = 768` (consumed by
`platform/layout.ts`), `HomeIndicatorInset = 34` (documented reference value
for QA/consumers; runtime prefers real insets). No renames/removals.

**Tests.** One new pure-logic file `src/platform/__tests__/platform.test.ts`
(6 tests, under the ≤8 cap): capability-flag coherence, off-web vibration
probe, hit-slop null/symmetric/fractional math, keyboard config mapping.

**Validation.** Single `npx tsc --noEmit` run from apps/mobile: zero errors in
W16-owned files (`screen-shell.tsx`, `theme/tokens.ts`, `src/platform/**`,
`sdk/audio-haptics-real.ts`). All 103 reported errors are parse errors in
`src/db/workout.ts` (W06 surface, observed mid-edit by a concurrent worker) —
not mine to touch.

**Navigation/storage audit (report-only, no code):**

  (`app/_layout.tsx` Stack) and must self-pad the bottom inset — ScreenShell
  does it centrally; screens need no changes.
