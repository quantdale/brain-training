## Implementation summary

**New module `apps/mobile/src/personalization/` (8 files + tests):**

- `types.ts` — stable `SignalKey` union (9 keys incl. `composition-fit`), structural row views (`DomainRatingView`, `GameAggregateView`, `RecentSessionView`) so callers pass db rows without casts, `PersonalizationOptions` (opt-in injectable `nowMs` + `staleDays`), immutable `PersonalizationContext`.
- `signals.ts` — the shared kernel + 8 signal-strength functions, each pure, [0,1]-bounded, with documented constants: weak domain (threshold pinned to `INITIAL_RATING`=1000, saturation at a 200-pt drop), undertrained domain (<3 sessions; unseen = 1.0), staleness (`isDomainStale` mirrors db `isRatingStale` exactly: strict `>`, non-positive horizon throws, missing timestamp/clock ⇒ never stale), novelty (linear decay to 0 at 3 lifetime sessions), game fatigue (clock-free: share of the last 10 overall sessions beyond a free allowance of 2), performance trend (recent-5 form vs lifetime avg, needs ≥3 sessions both sides, saturates at ±0.2, improving only), personal-best proximity (gap ≤0.15 to lifetime best, full at gap 0), difficulty fit (trapezoid over the productive band 0.3/0.45/0.75/0.9 on recent-form mean). Also `computeDomainSignals` (per-domain summary map) and `computeGameEvidence`.
- `weights.ts` — the complete transparent signed weight table (`SIGNAL_WEIGHTS`: weak +1.0, undertrained +0.6, stale +0.5, novelty +0.4, trend +0.4, PB +0.3, fit +0.3, overexposure −0.8, composition −0.6/repeat) with per-signal rationale, plus `PERSONALIZATION_VERSION = 2` and derived score bounds.
- `explain.ts` — two-layer explainability mirroring analytics conventions: fixed derivation sentences per signal key (`SIGNAL_EXPLANATIONS` / `explainSignal`) for UI captions, and instance reason formatters (`formatWeakDomainDetail`, `formatStaleDomainDetail`, …). The weak/stale formatters are word-for-word the legacy workout strings so both layers explain identical evidence identically.
- `context.ts` — `buildPersonalizationContext`: defensive sanitizing aggregation of repository rows (drops malformed rows, clamps normalized results to [0,1]); no db access.
- `scoring.ts` — `scoreGame`/`scoreGames`/`rankRecommendations` (stable sort, ties keep input order) producing `ScoredRecommendation { game, score, score01, components[] }` where every component carries `{key, weight, value, contribution=weight×value, reason}`; inactive signals emit NO component (no invented reasons). `selectRecommendations(games, context, count)` adds greedy workout-composition fit: each repeat of an already-picked primary category costs −0.6, applied transparently inside the picked entry's score/components.
- `index.ts` — barrel.

**Refactor `apps/mobile/src/workout/personalize.ts` (owned):**
- Now consumes the kernel: re-exports `WEAK_DOMAIN_RATING_THRESHOLD`/`STALE_DOMAIN_DAYS` from `@/personalization` (same pinned values), aliases `DomainRating` to the shared `DomainRatingView`, and computes tiers/reasons via `computeDomainSignals` + shared formatters instead of local duplicates. Local `isStale`/`DAY_MS`/detail-string duplication removed.
- Public surface unchanged: `personalizedWorkout`, `reorderByWeakDomains`, `rankByRecency`, `explainPersonalizedWorkout`, `WorkoutSelectionReason`, `PersonalizeOptions`, both constants, `DomainRating` — identical signatures and byte-identical ordering semantics (tier sort, stable tie-breaks, seed scheme `workout::<date>::<attempt>::personalized`). The V2 weighted scorer deliberately does NOT alter the pinned workout ordering; it layers on top for future consumers.

**Design decisions:** structural views instead of db imports (zero-I/O module, matches personalize.ts/analytics precedent); fatigue measured in sessions-not-days so it works without a clock while staleness stays opt-in; declining trend intentionally contributes 0 (decline is the domain signals' job); composition-fit is selection-time-only because it is set-relative.
