## Implementation summary

All six screens migrated to `<GameHost>` + `useGameSession` following the wave-1 exemplar method (`math-fast-math` / `speed-reaction-time`). Per game, only `screen.tsx` changed plus deletion of `components/pause-overlay.tsx`; reducers, generators, scoring, session, difficulty, hooks, tutorial, and other components are untouched.

Common rewiring applied to every screen:
- Removed per-screen `SessionLifecycle` ownership (`lifecycleRef`), local `randomSeed()`/`newSessionId()`, `finalizedRef`, manual `AppState` auto-pause subscription, intro/difficulty/start layout, in-session `SessionHeader`, results layout, pause-overlay mount, and a11y-hide wrapper — all now inherited from the host.
- Session identity/seeds via `session.begin()` + `resolveSessionSeed(sessionSeed)`; finalization via `session.claimFinalize()` / `completeIfActive()` / `elapsedMs()` / `pausedDurationMs()`; quit via `abandonIfActive()`.
- Pacing timers converted to pause-aware host helpers: odd-one-out round countdown → `useGameInterval`; quick-compare window expiry + order-path round expiry + transform-match source reveal + pattern-tap-back observe/recall timers → `useGameTimeout`.
- All existing semantic testIDs preserved (round/score/streak/pause/resume/board/tile/option/verdict/results/stat rows/QA panel/tutorial). Results views rebuilt on shared `<GameResults>` (provides `results`, `persist-error`, `forced-badge`, `restart`, `quit`); stat rows passed as children.
- Added `interceptBack={inSession}` (host hardware-back pause guard) matching exemplar convention — this is new behavior vs. these six screens (they had no back-guard before), consistent with the migrated catalog standard.
- Kept game-specific mechanics verbatim: odd-one-out pause remainder freeze (`pause {remainingMs}` captured in `onPause`) and resume rebuild (`resume {nowMs}`); quick-compare `pauseRemainingRef` re-anchor on resume; task-switch trial-origin pause shift (`trialStartRef`/`pauseStartRef`); order-path monotonic-epoch `startedAtMs: clock.now()` dispatch (deliberately NOT the wall-clock `identity.startedAtMs`, per its reducer contract) and its `QaPanel hooks={...}` prop shape; quick-compare header streak line passed through the host `header` slot (no `score` prop, preserving the `streak` testID).
- Dropped dead code where the migration made it clearly vestigial: unused `theme`/`escalatedGridSize` locals, quick-compare's never-referenced `handleTimeout` (verified unreferenced in the committed original).

## NEEDS_PARENT

1. GameHost QA-panel placement option (non-blocking, followed exemplar convention instead):
   - Required interface: optional `qaPanelPosition?: 'above' | 'below'` prop on `<GameHost>` (default `'below'`, i.e. current placement after children).
   - Why: `spatial-transform-match`'s pre-migration screen deliberately anchored the dev QA panel ABOVE the tall board content ("so they stay reachable by automation — the board pushes anything rendered below it past several viewport-heights"). The host renders `qaPanel` after children, so on very small viewports the panel may sit below the fold for that game.
   - Consumer: `games/spatial-transform-match/screen.tsx` (and potentially other tall-board games).
   - Resolution taken: migrated with host-default placement, matching all six wave-1 exemplars (including grid-heavy `attention-visual-search` and `spatial-fold-match`, which also use host-default placement). No duplicate panels were introduced. If the parent adds the prop, flipping this one game is a two-line change.
