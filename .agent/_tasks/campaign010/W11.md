# W11 — Database / Repository API Maturation

## Mission

Single DB-focused worker. Implement broader repository APIs needed for future scale, preserving migration compatibility and avoiding gratuitous schema changes.

Candidate work:
- projection queries (column-limited reads)
- pagination + windowed analytics primitives
- aggregate queries (COUNT/SUM/AVG pushdown helpers)
- lightweight session records (projection DTOs)
- bulk reads + safe batch operations
- transaction helpers
- typed query result types
- index-aware APIs (verify existing indexes in `schema.ts` before relying on them)

HARD constraints:
- You own db core: `db/adapter.ts`, `db/adapters/**`, `db/sessions.ts`, `db/profile.ts`, `db/rating.ts`, `db/favorites.ts`, `db/tutorial.ts`, `db/types.ts`, `db/index.ts` (ADDITIVE re-exports only — other workers' modules are re-exported there; do not remove or rename existing exports).
- NOT yours: `db/workout.ts` (W06), `db/achievements|quests|economy|ledger|xp-awards.ts` (W12), `analytics/**` (W08/W09).
- `schema.ts`/`migrate.ts`: granted exception ONLY if the production implementation genuinely requires it. Any change must preserve migration compatibility for existing installs (append-only, versioned, collision-safe patterns per 009's v8 lesson). Document any schema change prominently.
- W09 owns `analytics/queries.ts`; if they request a db primitive via parent, implement it generically in the db layer.
- Do not run benchmark campaigns.
