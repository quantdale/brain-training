## Implementation summary

Landed (all inside owned paths):

1. **Audit A1 — unused native dependency verification.** Method: substring import scan across all of `apps/mobile/src` (+ `jest/`, `scripts/`, root config files), then reverse-dependency scan of every installed `node_modules/*/package.json` and `node_modules/@expo/*/package.json`. Full result handed to parent under "Shared changes requested" above. Key discovery: `@expo/ui`, `expo-glass-effect`, `expo-symbols` are hard deps of expo-router itself, so removing our direct declarations changes nothing about what is installed or linked.

2. **Audit A4 — Android permission overreach, trimmed at both sources.**
   - `app.json`: bare `"expo-audio"` plugin replaced with `["expo-audio", { "microphonePermission": false, "recordAudioAndroid": false, "enableBackgroundPlayback": false }]`. Verified against the actual shipped plugin source (`node_modules/expo-audio/plugin/build/withAudio.js`): `recordAudioAndroid:false` stops RECORD_AUDIO injection; `enableBackgroundPlayback:false` stops FOREGROUND_SERVICE + FOREGROUND_SERVICE_MEDIA_PLAYBACK and the `expo.modules.audio.service.AudioControlsService` media3 service; `microphonePermission:false` omits NSMicrophoneUsageDescription on iOS. App only plays short SFX, so background playback/recording services were pure overreach.
   - `AndroidManifest.xml`: removed RECORD_AUDIO, SYSTEM_ALERT_WINDOW, READ/WRITE_EXTERNAL_STORAGE (our `tools:replace` copies were value-identical to expo-file-system's library declarations, which still merge in capped at maxSdkVersion=32), FOREGROUND_SERVICE(_MEDIA_PLAYBACK), VIBRATE (merges from expo-haptics), the now-unused `xmlns:tools`, and the AudioControlsService block. Kept INTERNET + MODIFY_AUDIO_SETTINGS. Policy rationale captured as an XML comment in the manifest.

3. **Audit B7 — auto-backup policy.** Decision: keep `allowBackup="true"` (non-progress settings survive device restore) but exclude the entire SQLite database domain from cloud backup AND device-to-device transfer, so wiped progression data cannot be resurrected by a restore. New files: `android/app/src/main/res/xml/data_extraction_rules.xml` (API 31+: `<cloud-backup>` + `<device-transfer>` excludes) and `android/app/src/main/res/xml/backup_rules.xml` (API ≤30 `<full-backup-content>` exclude); wired via `android:dataExtractionRules` / `android:fullBackupContent` on `<application>`. Both files needed because minSdk=24 (ExpoRootProjectPlugin default 24; no `gradle/libs.versions.toml` override) < 31. Coverage check: no AsyncStorage/RKStorage usage anywhere in src, so the database-domain exclusion covers all canonical persistence (expo-sqlite).

4. **Plugin config review.** splash-screen options valid (#208AEF/image/imageWidth 76), sqlite bare = fine, asset bare = fine (unused `assets` option), sharing bare = consistent with keeping the dep, router bare = fine, `experiments.typedRoutes/reactCompiler` fine, `ios.icon` `.expo.icon` liquid-glass format fine. Only real misconfiguration found was expo-audio (fixed).

5. **Web/platform conditionals.** Report-only per contract: all `Platform.OS` usage lives in W16-owned files (`screen-shell.tsx`, `theme/tokens.ts`); the only `.web` files are `src/components/app-tabs.web.tsx` (shell component → W13 territory) and `src/hooks/use-color-scheme.web.ts` (trivial hook). No unowned cleanup targets found; nothing edited outside my surfaces.
