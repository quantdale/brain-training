# W02 — Speed Catalog Expansion: new distinct Speed mechanic

## Mission

Study the current Speed catalog (`speed-color-match`, `speed-quick-compare`, `speed-reaction-time`, `speed-tap-rush`) and implement ONE genuinely new mechanic as a complete production vertical slice.

Candidates (evaluate, then commit to the best):
- choice reaction under changing stimulus→response mappings
- rapid ordering under time pressure
- paced precision tapping (timing accuracy vs a seeded metronome)
- visual comparison stream

Hard constraints:
- Do NOT create another Tap Rush or Quick Compare clone.
- Do NOT build a rare-target go/no-go / SART mechanic — W01 owns sustained-vigilance go/no-go this campaign; overlapping it wastes a worker.
- Document the distinctness rationale vs all four existing Speed games AND vs W01's mechanic in your summary.

Build the complete production module per README §7: game metadata (`game.json`), difficulty, generation, state/reducer, session, scoring, screen, tutorial, components, hooks, QA seam (dev-gated), sensory integration, accessibility, deterministic seeds, injectable clock, pause/resume freeze, AppState auto-pause, adaptive-profile seam, registry-ready metadata. ≤8 small determinism tests allowed; no test suites.

Module id: `speed-<mechanic>` following the `<domain>-<mechanic>` convention.
