## Implementation summary

**New shared shell components** (`apps/mobile/src/components/shell/`, all built only on existing primitives — ThemedText/ThemedView/MinTouchTarget/theme tokens):
- `state-card.tsx` — one consistent empty/loading/error card (polite live region, optional single recovery action pill, ActivityIndicator for loading).
- `section-header.tsx` — subtitle + caption + optional right-aligned drill-down action ("See all" pattern); router-free (onPress callback) so typed-route casts stay at call sites.
- `stat-tile.tsx` — value/label tile matching Home's pinned stat-card visual contract exactly.
- `info-row.tsx` — label/value row replacing the duplicated ResultRow/DetailRow copies in results/game-detail.
- `progress-track.tsx` — tokenized thin progress bar (theme accent fill, clamped ratio, progressbar a11y role + accessibilityValue).
- `format.ts` — pure helpers: `formatRelativeDay(ts, now)` (local-midnight day diff → Today/Yesterday/N days ago/locale date) and `performanceBand(ratio)` (encouraging non-clinical headline bands per constitution §4/§16).
- `index.ts` barrel; `__tests__/format.test.ts` with 7 capped determinism tests for the pure helpers.

**Home** (`(tabs)/index.tsx`): focus-refresh (refreshKey via useFocusEffect) so every slot updates after playing; explicit loading hint (`home-loading`); recoverable error card with Retry (`home-data-error`, gated on loaded+error+non-empty catalog so bare-harness fallbacks stay static); workout completion ProgressTrack (`home-workout-progress-bar`); primary "Continue workout →" CTA at the durable resume position (`home-workout-continue`); per-game category captions + richer a11y labels on workout rows; quick-action pills Browse games / Progress / Rewards (`home-quick-actions*`, gated on populated workout); coins StatTile when balance > 0 (`home-stat-coins`); recent-games rows now show relative day + XP with a Results drill-down header action (`home-recent-all`). First-run/empty render tree kept byte-identical for the canary snapshot.

**Games** (`(tabs)/games.tsx`): per-category counts on filter chips ("Memory · 7", "All · 38"); live result-count line (`games-count`); favorite ★ moved into the card header row (badge semantics); no-results state upgraded to StateCard with one-tap Clear-filters action (`games-no-results` + `games-no-results-action`). Empty-catalog state untouched (pinned).

**Game Detail** (`game-detail/[id].tsx`): Play CTA promoted to filled accent pill with 44pt min touch target; Records card gains "Last played" relative-day row (aggregate.lastCompletedAt was previously fetched but never shown); tutorial hint caption when `game.hasTutorial`; session rows use relative-day labels; unknown-game fallback copy improved (testIDs preserved). Removed now-duplicated local DetailRow.

**Results** (`results.tsx`): explicit loading StateCard (`results-loading`); performance-band headline over the raw percentage (`results-band`, tone-mapped success/accent/warning); empty state is now actionable StateCard with "Browse games" (`results-empty` preserved); InfoRow adoption for metrics/rating rows.

**Data Management** (`data-management.tsx`): consumes W10's transport seam as-is — module-level `createMemoryTransport()`; every export also saved under `defaultBackupName()`; new Saved Backups card lists session-scoped backups with Load (fills import box) / Delete actions (`data-saved-backups`, `data-backup-load-*`, `data-backup-delete-*`); XP-awards count tile added (`data-count-xp`); accessibilityLabels added to all operation buttons; copy states the session-only scope honestly until a file-system transport lands.

**Storage unavailable** (`storage-unavailable.tsx`): added a 3-step "what you can do" guidance list between message and diagnostic detail; retry button gained label+hint; still deliberately self-contained plain-RN (no theme/db deps — those are what may have failed). All contract testIDs preserved.

**Intentionally untouched:** `app/game/[id].tsx` (packet says minimal/careful; its header testIDs are asserted QA surface and the lazy-host structure is already correct).

**Design decisions:** (1) snapshot-pinned fallback trees kept byte-stable by gating all additions behind real data or non-empty branches — no canary regeneration needed for this wave; (2) error surfacing on Home gated on non-empty catalog because with an empty registry a db failure is the expected bare-harness condition; (3) new components take onPress callbacks rather than hrefs to keep typed-route casts out of shared code; (4) memory transport used as-is per packet ("consumes W10's transport API as-is") with explicit session-scope copy rather than pretending persistence.

**Validation:** two `npx tsc --noEmit` runs from `apps/mobile` (initial + post-fix verify of the same check). Final run: zero errors in any owned file (`src/app/**`, `src/components/shell/**`). Remaining tsc errors originate in other workers' concurrent surfaces (`src/games/*`, `screen-shell.tsx`, `workout/summary.ts`) — not touched per ownership rules. One fix applied to my code: `loaded && error && …` chain typed `unknown` → changed to `error != null` ternary guard.
