# W13 — UX / Navigation / Information Architecture

## Mission

Broad production UI implementation across the shell screens you own. Use the existing visual/design system; NO total visual redesign. This is implementation, not screenshot QA.

Focus screens:
- Home (`app/(tabs)/index.tsx`) — incl. Today's Workout surfacing via W06's engine APIs (read-only consumer)
- Games (`app/(tabs)/games.tsx`) + Game Detail (`app/game-detail/[id].tsx`) + game launch route (`app/game/[id].tsx` — minimal, careful edits only)
- Profile (`app/(tabs)/profile.tsx`)
- Results (`app/results.tsx`)
- Data Management (`app/data-management.tsx`) — consumes W10's transport API as-is
- Storage unavailable (`app/storage-unavailable.tsx`)

Implement missing:
- empty states, loading states, error states
- section hierarchy + information density
- navigation affordances, quick actions, contextual summaries
- consistent cards/headers, better drill-down paths

You may create NEW shared presentational components under `apps/mobile/src/components/shell/**` (cards, section headers, empty/error/loading state components). Consume existing primitives (`components/a11y.ts`, `game-ui/**`, `screen-shell.tsx`) — do not edit them.

HARD constraints:
- Navigation registries are parent-owned: do NOT edit `app/_layout.tsx` or `app/(tabs)/_layout.tsx`. NEEDS_PARENT for route changes.
- Progress screens = W08; rewards screen = W12; workout engine internals = W06.
- Keep route-param runtime guards (xplat audit B9 pattern) in any new deep-linkable surface.
