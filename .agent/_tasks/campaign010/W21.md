## Implementation summary
- **`src/sdk/perf.ts` (NEW)** — dependency-free mark/measure module, no-op everywhere behind `isDevBuild()` (same gating as `types/qa.ts`):
  - Versioned record shape (`PERF_SCHEMA_VERSION = 1`): `{ schemaVersion, kind: 'mark'|'measure', name, atMs (wall clock, correlates with DiagnosticMetadata.startedAtMs), durationMs? (monotonic), gameId?, detail? }`.
  - Stable event-name union: `game-session-start`, `game-first-interaction-latency`, `session-persist-duration`, `progress-snapshot-load`.
  - Generic primitives `markPerfEvent()` / `startPerfMeasure()` plus domain helpers `markGameSessionStart()`, `markGameFirstInteraction()`, `trackSessionPersist()`, `trackProgressSnapshotLoad()`. Measure handles end exactly once; un-ended measures never reach the buffer; production builds get a no-op handle.
  - Ring buffer (`PERF_RING_CAPACITY = 128`) + dev readout seam `getRecentPerfRecords(): readonly PerfRecord[]` (returns `[]` outside dev builds, safe for unconditional QA calls).
  - Emission into the structured-log pipeline: single-line JSON via `console.log("[perf] {…}")`, matching the repo's `[module] payload` convention so QA artifacts can grep it. (`sdk/types/diagnostics.ts` itself was NOT edited — not an owned path; record types live additively in `perf.ts`.)
  - Determinism seams: durations from the shared injectable monotonic clock (`timing.ts`); `setPerfClockForTests(clock)` + `resetPerfForTests()` for deterministic tests/QA.
- **`components/game-host/use-game-session.ts`** — `begin()` now calls `markGameSessionStart(gameId)` after the lifecycle starts (opens the latency window). No API/behavior change.
- **`components/game-host/game-host.tsx`** — session view body got a passive `onTouchStart` calling `markGameFirstInteraction(gameId)` (closes the window; does not participate in responder negotiation). The Start-button press itself cannot self-report because arming happens at `begin()` after that touch's `onTouchStart` has already passed.
- **`components/game-host/results.tsx`** — effect brackets `<GameResults>`'s `persistState` lifecycle: opens `trackSessionPersist(gameId)` at first `'started'`, ends at `'succeeded'`/`'failed'` (`outcome` detail), or records `'superseded'` if persistence state returns to `'idle'`. Unmount mid-write drops the sample rather than recording a truncated duration.
- **`analytics/projections.ts`** — `tryLoadProjectedSessionRows` wrapped with `trackProgressSnapshotLoad()`; detail records resolved tier (`path: 'repository' | 'transaction' | 'none'`) + `outcome` (`rows`/`fallback`/`error`) + `rowCount`. Return values and fallback order unchanged (note: W22 refactored this file mid-wave to repository primitives + transaction-seam fallback; instrumentation targets the current two-tier path as found).
