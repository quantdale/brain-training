## Implementation summary

**Landed:** one complete new Memory game, `apps/mobile/src/games/memory-prospective-cue/` ("Signal Watch") — event-based **prospective memory**: form intentions in a briefing, hold them across a filled delay with NO on-screen reminders, and act (tap SIGNAL vs ongoing GO) the moment a held signal appears in a speeded stream.

**Distinctness rationale (vs all catalog neighbors):**
- All 6 existing Memory games are RETROSPECTIVE: `memory` + `memory-sequence-memory` (Simon reproduction), `memory-grid-recall` (spatial bitmap rebuild), `memory-pattern-tap-back` (span tap-back), `memory-running-order` (recency recall of last-N stream items), `memory-pair-recall` (associative cued recall with re-pairing interference). Signal Watch has no recall/reproduction phase at all: studied content is never re-displayed; stream items are never recalled — they trigger stored intentions. Interference comes from intention maintenance/updating across delays, not from re-pairing.
- Near-neighbors outside Memory: `flexibility-cue-shift`/`rule-flip` show the active rule ON SCREEN at decision time (rule knowledge is never the demand); `attention-symbol-tracker`/`target-count` are perceptual tracking/counting; `speed-*` have no stored intentions; Logic games deduce from presented info. Remembering TO ACT at a future moment is unrepresented → clearest gap.

**Mechanic details:** per round: briefing (NEW signals shown once as glyph chips; retirements announced; survivors counted but never named) → stream of `streamLen` items each within an `itemMs` window (tap GO for fillers / SIGNAL for active signals / timeout = miss). Each active signal appears EXACTLY once per stream (generator invariant). Round passes only on a perfect prospective component (all signals caught, zero false alarms); GO slips cost points but don't fail the round. Escalation on pass: +1 simultaneous signal (to max) and −150 ms window (to floor). Adaptive moves signal count ±1 within [2, max].

**Key files:** `game.json`, `types.ts`, `glyphs.ts` (12-glyph palette), `difficulty.ts`, `generator.ts` (`generateRound`/`splitCarryOver`/`validateRound` oracle/near-dup guard), `reducer.ts` (pure FSM incl. qa/*), `scoring.ts` (documented item table + normalization `signalAccuracy*(0.6+0.4*accuracy)`), `session.ts` (raw result + db persistence seam), `hooks.ts`, `versions.ts`, `game-definition.ts`, `index.ts`, `screen.tsx`, components (`stream-view`, `briefing-panel`, `response-controls`, `tutorial`, plus button/pause-overlay/qa-panel shared adapters), `__tests__/generator.test.ts` (6 tests).

**Conventions honored:** deterministic seeded generation (per-round RNG forks), injectable clock, freeze-and-continue pause for both lifecycle and per-item window, AppState auto-pause, dev-gated QA force-win/lose/state via assertDevOnly + QaPanelShell behind isDevBuild(), semantic testIDs exclusively through `testId()`, TutorialFrame tutorial with QA skip, sensory via canonical `liveAudioHaptics.feedback(...)` events only, a11y: glyph identity labels never reveal signal status, challenge hidden from accessibility tree while paused, adaptive-profile seam (params in resolved profile + sessionChallengeRating), registry-ready game.json (id matches dir).
