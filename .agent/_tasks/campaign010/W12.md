## Implementation summary

Engagement V2 landed as purely additive slices over the 009 architecture. No
schema changes, no migration, no criteria/reward edits to existing
definitions (backward compat with all existing tests preserved).

**1. Multi-stage achievement chains** — `src/achievements/chains.ts` (+ index exports):
5 named chains (`chain-sessions`, `chain-xp`, `chain-streak`, `chain-active-days`,
`chain-perfect`) built from explicit stage-id lists over EXISTING definitions;
`resolveChainProgress(chain, definitions, snapshot)` returns completedStages /
currentStage / nextRatio / complete using the existing pure progress evaluator.
Unknown stage ids throw at resolve time (typo fails loudly). Also added
`TIER_ORDER` / `tierRank` for tier presentation ordering. Categories + rarity
tiers themselves already existed from an earlier wave — verified, not duplicated.

**2. Quest refresh/history** — `src/quests/refresh.ts`, `src/quests/history.ts`,
+ additive repo methods in `db/quests.ts`:
- `nextRefreshAt(kind, now)` / `msUntilRefresh`: daily → next local midnight,
  weekly → next ISO-week Monday 00:00 local, longterm → null (never rotates).
  Pure, injectable-clock friendly, mirrors `period.ts` conventions.
- `summarizeQuestHistory(rows)`: per-quest lifetime {periodsPlayed, completions,
  claims, lastCompletedPeriod, lastClaimedPeriod} projected from the implicit
  (questId, period) row history; lexicographic max = chronological max for the
  zero-padded period keys.
- `QuestRepository.listProgressForQuest(id)` and `.listAllProgress()` (additive).

**3. Reward inbox + claim-all** — `src/rewards/inbox.ts`:
`collectClaimableRewards(db, now)` unifies unlocked-unclaimed achievements,
completed-unclaimed active quests (progress ≥ goal re-checked), and
reached-unclaimed streak milestones into one deterministic list
(`achievement:<id>`, `quest:<id>:<period>`, `milestone:<id>` keys).
`claimReward` dispatches each item through its CANONICAL once-only flow
(`claimAchievementReward` / `applyQuestReward` / `claimStreakMilestoneReward`),
so idempotency is inherited from the 009 gates (`claimed_at IS NULL`,
persisted `claimedMilestones`, unique partial-index operationIds) rather than
reinvented. `claimAllRewards` loops and aggregates; an immediate second pass
claims nothing. Stale items (period rolled over between collect and claim)
map honestly to `{status:'unavailable'}` via the typed
`QuestNotCompleteError`. Best streak is re-derived at claim time so a stale
collect snapshot can never claim an unreached milestone.

**4. Reward history feed** — `src/rewards/history.ts` + additive
`LedgerRepository.listRecent(limit)` (DESC; `list` keeps append-order contract):
pure `mergeRewardHistory(xpAwards, ledgerEntries, limit)` projects both
append-only records into one newest-first feed with stable ids (`xp:<rowId>` /
`coins:<rowId>`) and label mapping (`describeXpSource`, `describeLedgerReason`)
covering gameplay/quest/achievement/streak-milestone/cosmetic/reroll/streak-item
reasons. This doubles as unlock provenance for XP/coin grants.

**5. Cosmetic collection progress + provenance** — `src/cosmetics/collection.ts`:
`collectionProgress(definitions, progression, settings)` → per-slot + overall
owned/total/ratio; `cosmeticProvenance(def, progression, settings, evidence)`
derives how/when each cosmetic was earned from authoritative evidence maps
(ledger `cosmetic:<id>` entry timestamps, achievement unlock claims, quest
claims) — DERIVED, never stored, so it cannot desync. Missing evidence
degrades to earnedAt:null + explanatory hint.

**6. Rewards hub screen** — `app/rewards.tsx` deepened in place: balance card
(kept) → NEW "Ready to claim" inbox card (per-item Claim buttons +
`rewards-claim-all`, empty state, celebrations on claim) → NEW Collection
progress card (overall % + per-slot bars) → existing cosmetic slots grid
(equip/buy unchanged) → NEW Recent-rewards history card (last 8, date +
amount). All new controls carry semantic testIDs
(`rewards-inbox`, `rewards-claim-all`, `reward-claim-<sanitized-key>`,
`rewards-collection*`, `rewards-history*`) and accessibilityRole/Label; the
double-tap busyRef guard now covers claims too.

**7. Tests** — `src/rewards/__tests__/engagement-v2.test.ts`: exactly 8 pure
determinism tests (chain resolution incl. unknown-id throw, refresh
boundaries, history summarizer, label mapping, merge order, collection math,
purchase provenance). No db-dependent test added.
