## Implementation summary

All four mission items implemented; both wave-1 NEEDS_PARENT items resolved as specified.

1. **`db/sessions.ts`** — new exported interface `SessionProgressRow` (11 scalar columns + `mScore/mAccuracy/mReactionMs/mDifficultyRating/mDifficultyLevel`, field docs preserved) and new `SessionRepository` methods `listProgressProjection(limit)` / `listProgressProjectionByGame(gameId, limit)`. The guarded `json_valid`/`json_extract` SQL construction moved verbatim from `analytics/projections.ts` into a clearly-marked section at the end of this file (canonical home; db may not import analytics, analytics already imports db). Exports added: `SessionProgressRow`, `DIFFICULTY_LEVEL_PARAMS`, `PROJECTED_SESSIONS_ALL_SQL`, `PROJECTED_SESSIONS_BY_GAME_SQL`. Methods are plain `adapter.all` reads on the shared connection — no transaction seam. `limit` is validated with `requireFiniteNumber` + floored but deliberately NOT clamped to `MAX_READ_LIMIT`: analytics callers pass "effectively everything" limits (`ALL_SESSIONS_LIMIT = 1_000_000`) for lifetime aggregates, and clamping would make the fast path return different data than the legacy full-row fallback. New import `DIFFICULTY_LEVELS` from `@/sdk/types/difficulty` (subpath style matching `db/tutorial.ts`; verified no sdk→db import cycle exists).
2. **`db/workout.ts`** — added `WorkoutRepository.listRecent(limit = 30): Promise<WorkoutInstance[]>`, delegating to `listHistory({ limit })` → primary-key `date DESC` ordering (daily row before same-day namespaced template keys), exactly W08's spec. No existing member touched.
3. **`analytics/projections.ts`** — `tryLoadProjectedSessionRows` now tries, in order: (a) repository primitives (fast path; also keeps working inside an outer transaction where `db.transaction()` refuses to nest), (b) the former `db.transaction()` seam path unchanged (JSON1 probe memoization retained), (c) `null` → callers fall back to legacy full-row reads. Local SQL construction/interface deleted; `ProjectedSessionRow`, `DIFFICULTY_LEVEL_PARAMS`, `PROJECTED_SESSIONS_ALL_SQL`, `PROJECTED_SESSIONS_BY_GAME_SQL` remain exported under their historical names via re-exports from `@/db/sessions`, so `queries.ts` (W09-owned, untouched) and `analytics/__tests__/projections.test.ts` compile and their assertions (`json_valid(raw_result_json)`, `ORDER BY completed_at DESC`, `WHERE game_id = ?`, level bindings) hold by construction — the SQL text is byte-identical.
4. **`app/(tabs)/progress.tsx`** — the 28-iteration `getByDate` date-key walk replaced by one bounded read `(await db.workouts?.listRecent?.(WORKOUT_RECENT_LIMIT)) ?? []` with `WORKOUT_RECENT_LIMIT = 30`. Data-gating behavior identical: same optional-chaining degradation (workout card hides when repository unavailable), same `hasWorkoutData = workouts.length > 0 || workoutsCompletedLifetime > 0` gate, same `buildWorkoutAnalytics(workouts, lifetime)` consumption. Removed now-unused `DAY_MS`, `localDateString` import. One visible copy change forced by the semantics swap: summary label `Done (28d)` → `Done (last 30)` (the loaded set is no longer a day-window; flagging for parent awareness).
5. **`db/index.ts`** — additive only: `export type { SessionProgressRow } from './sessions'`.

No schema changes; no existing export/signature removed or altered; no git commands run; no shared hotspots touched.
