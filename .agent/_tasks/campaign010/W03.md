## Implementation summary

**Landed:** complete production module `apps/mobile/src/games/math-value-ordering/` ("Value Order", id `math-value-ordering`, 17 files) — numeric-ordering mechanic: each round shows 3–6 tiles in seeded shuffled display order; the player taps them smallest→largest under a per-round time budget. Correct taps lock tiles with rank badges; one wrong tap ends the round as a mistake; budget exhaustion is a timeout; tapping all tiles in ascending order is a perfect round scored 100–150 by remaining-budget fraction.

**Files:** `game.json`, `game-definition.ts`, `types.ts`, `difficulty.ts`, `generator.ts`, `scoring.ts`, `reducer.ts`, `session.ts`, `hooks.ts`, `versions.ts`, `screen.tsx`, `index.ts`, `components/{button,value-grid,pause-overlay,qa-panel,tutorial}.tsx`, `__tests__/value-ordering.test.ts` (8 tests).

**Design decisions:**
- *Distinctness rationale vs all four existing Math games:* Fast Math = produce an arithmetic answer; Missing Operator = identify which operator makes an equation true; Equation Builder = plan/construct a multi-step expression toward a target; Number Line = interpolate ONE position on a continuous scale (no set comparison). Value Order = **ordinal ranking of a SET of quantities** — relational magnitude comparison under time pressure, with some values disguised behind quick expressions (`6 × 4`) so higher difficulties blend comparison with light computation. No answer production, no operator selection, no expression construction, no spatial interpolation.
- *Ambiguity-free by construction:* comparison values are pairwise-distinct integers (collision re-draws + deterministic sequential-probe fallback), so "the smallest remaining tile" is always unique; `validateRound` guards this invariant.
- *Determinism:* per-round RNG forks (`round:<i>:attempt:<n>`, per-tile child streams `tile:<j>`); consecutive-round variety re-draws; same `(seed, difficulty)` always reproduces the session. Expressions use swap-normalized subtraction (non-negative results, operands stay in range).
- *Difficulty:* easy/normal/hard/expert tune rounds/budget/tile count/value range/expression mix; `adaptive` moves tile count ±1 within [3, 6] (perfect → harder) and maps final count linearly onto challengeRating [0, 1] (neutral start = 0.5 baseline). Strict `paramsFromProfile` validation rejects degenerate configs (range too small to host distinct values).
- *Timing/pause:* reducer never reads a clock; ticks/taps carry lifecycle active-ms; past-budget taps converge on timeout exactly like the tick path; pause freezes the ticker and hides the board via shared opaque PauseOverlay + `accessibilityElementsHidden`/`importantForAccessibility="no-hide-descendants"`.
- *QA seam:* dev-gated QaPanel (QaPanelShell) + `qa/force-win|lose|state` reducer actions behind `assertDevOnly()`; force-win fabricates a deterministic perfect session (normalized exactly 1.0, flagged `forced`).
- *Sensory:* literal canonical calls only — `feedback('tap')` on tile press, `feedback('correct'|'wrong')` on resolution (scanner-clean).
- *A11y:* tiles announce only their own visible display text (never relative order — no solution leak through the accessibility tree); semantic testIDs throughout via `testId(GAME_ID, …)`.

**Report-only proposal (existing Math games — not owned, NOT implemented):**
1. `math-fast-math`: expert could add two-step problems (`a × b + c`) at generatorVersion bump; current single-op ceiling caps expert differentiation.
2. `math-missing-operator`: hard/expert could widen to include squared terms or missing-operand variants (distinct from operator choice) — needs its own ambiguity analysis first.
3. `math-number-line-estimation`: expert's [0, 1000] line could switch to non-zero origins (e.g. [250, 750]) to force true interpolation rather than anchor-relative taps.
4. `math-equation-builder`: curated template bank is small (20); expanding per-difficulty template pools would deepen content without touching mechanics.
