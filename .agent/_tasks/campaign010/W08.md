### NEEDS_PARENT: WorkoutRepository bulk read (optional, efficiency only)
- Required interface: `listRecent(limit: number): Promise<WorkoutInstance[]>` (or `listSince(date: string)`) on `WorkoutRepository` (`apps/mobile/src/db/workout.ts`, owner W11/W06).
- Why: the overview currently loads 28 days of workout instances via 28 primary-key `getByDate(date)` point lookups in parallel. Correct and bounded, but one indexed range query would be cheaper and would let the lookback grow without more round trips.
- Desired signature: `listRecent(limit = 30): Promise<WorkoutInstance[]>` ordered by `date` desc.
- Consumer: `apps/mobile/src/app/(tabs)/progress.tsx` (`load()`). Not blocking — shipped implementation works against the existing API as-is.

## Implementation summary

All work inside owned surfaces; `analytics/queries.ts`, `db/**`, registry, manifests untouched. No git commands run. No medical/effectance wording anywhere — new captions are neutral derivations, and the co-occurrence view ships an explicit "co-occurrence, not cause and effect" disclaimer (`COOCCURRENCE_CAPTION`).

New pure modules under `apps/mobile/src/analytics/` (all deterministic, injectable `nowMs`, no clock reads):
- `trend-summary.ts` — `summarizeTrend` / `summarizePointTrend` (first/last/delta/min/max/mean/stdDev/consistency/least-squares slope-per-day) + `trendImproved(read)` for higher-better / lower-better / neutral metrics.
- `volume-view.ts` — `buildSessionVolume`: window vs immediately-preceding equal-length window counts, delta + direction, active days, sessions/week, weekly bucket array (empty for `all`).
- `metric-trends.ts` — generic extracted-metric trend over sessions via `metrics-map`; `buildAccuracyTrend` / `buildReactionTrend` with recent-mean (last 5) and availability flags (never fabricates missing metrics).
- `difficulty-progression.ts` — first/latest/peak challenge rating, delta, at-or-above-lifetime-median share; explicitly neutral presentation.
- `personal-best.ts` — strictly-improving PB event chain (ties keep earliest), current/previous best, times beaten, standing days; normalized + raw-score variants.
- `rolling-windows.ts` — `rollingAverages` (aligned trailing means), `buildRollingAverageSeries`, `compareRates` (recent vs lifetime sessions-per-week).
- `category-comparison.ts` — per-domain rows combining `DomainInsight` ratings/movement with in-window sessions/avg/best/last-played attributed by primary category (same attribution rule as training-balance so both views agree).
- `workout-analytics.ts` — pure aggregation over loaded `WorkoutInstance[]` + lifetime completed count: completion rate, games assigned/completed sums, current & longest consecutive completed-day runs (local-date keys, gap = break).
- `cooccurrence.ts` — groups days by distinct-domain breadth and restates avg normalized per breadth group; ships mandatory co-occurrence disclaimer constant.

Additive extensions to existing owned modules (no export removed):
- `training-balance.ts` — `balanceCoverage`, `balanceEffectiveDomains` (inverse-Simpson evenness), `buildWeeklyBalance` (4×7-day slices, canonical domain order kept so stacked-bar colors stay stable across weeks).
- `activity-calendar.ts` — `activeRuns` (current/longest consecutive active days within the window), `weekdayDistribution` (+`WEEKDAY_LABELS`), `monthlyActivity`.
- `insight-notes.ts` — 12 new explainability keys/captions (trend-summary, volume, accuracy/reaction-trend, difficulty-progression, personal-best-history, rolling-average, category-comparison, workout-completion, cooccurrence, diversity, activity-runs, weekday-pattern).
- `index.ts` — re-exports all new modules.

Charts (`components/progress-charts.tsx`): added `CompareBars` (two-track labeled comparison) and `LabeledBars` (labeled vertical distribution bars); both presentational, deterministic, theme-aware, testID-passing. Existing primitives unchanged.

Screens:
- `(tabs)/progress.tsx` — loader now also walks 28 days of persisted workouts read-only (`db.workouts?.getByDate?.()` + `countCompleted()`, optional-chained so partial db fakes/degraded dbs degrade to hidden cards instead of crashes). New cards: Session volume (CompareBars vs previous window + weekly MiniBarChart + delta arrow), Personal best (best/set/standing/times-raised), Workout completion (rate, runs, games finished, all-time), Category comparison (linked rows to `/progress-domain`), Training breadth & results (co-occurrence + disclaimer). Balance card gains evenness line + week-by-week share strips; RecentVsLifetimeCard gains a rolling last-5 average line. New-player guard hides volume/balance-extras/PB/categories/co-occurrence exactly like the existing balance-card guard.
- `progress-game.tsx` — Trend summary card (consistency, ±1σ swing, slope/day, colored direction), Rolling average chart, Best-result history (normalized PB chain, last 5 events + standing/times-beaten), Score-record history (when ≥2 score PBs exist), Difficulty progression block (first/latest/peak/at-or-above-median, neutral coloring). Existing trend blocks and records untouched (existing render tests keep their labels/testIDs).
- `progress-domain.tsx` — Trend summary card over the domain's rating series (in-window when ≥2 updates, all-time fallback matching the chart's rule), plus Accuracy-over-time, Reaction-time (lower-is-better label), and Difficulty-attempted cards built from the domain's own sessions; each only renders when its metric exists.
- `progress-activity.tsx` — Current/longest active-run stats in the summary card, Weekday pattern card (LabeledBars + per-weekday rows), By-month rollup card (partial months honestly labeled).
- `progress-detail.tsx` — loader widened from 10 to 120 recent sessions for aggregates while the visible list stays capped at 10; new Recent personal bests, Rolling average, Accuracy-over-time, Reaction-time cards (availability-gated).

Tests: `src/analytics/__tests__/analytics-v2.test.ts` — exactly 8 determinism tests (one per core new module contract), fixed clock `2026-01-20`, no suites beyond one describe block, per campaign validation policy.

Design decisions:
- Workout consumption stayed strictly read-only through the existing repository API; the bounded `getByDate` walk avoids touching W06/W11 surfaces (see NEEDS_PARENT for the optional bulk-read improvement).
- Category comparison reuses `DomainInsight` rather than recomputing rating movement, so overview/domain/comparison views can never disagree.
- Weekly balance keeps canonical domain ordering (not count ordering) deliberately, so `StackedShareBar` palette colors are stable week-to-week.
- All new screen cards are gated on data presence or the new-player flag, keeping the db-unavailable/new-player visual baseline stable (matches the existing render-test expectations).
