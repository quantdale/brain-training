## Implementation summary

Rewrote the Progress query layer onto a SQL projection/pushdown architecture (evidence: `scripts/perf/baselines/perf-baseline-2026-08-21T03-17-12-656Z.json` — `loadProgressSnapshot_20000_ms ≈ 107`, dominated by `listRecent(1M)` full-row materialization ≈108 ms; `listLightweight_20000_projection_ms ≈ 15` shows the projection class target).

Files (all created/edited by W09):
- `apps/mobile/src/analytics/projections.ts` (NEW) — narrow SELECT over `game_sessions` returning all scalar columns plus per-row metrics extracted in SQLite via guarded `json_extract`/`json_type`/`json_valid` (mirrors `metrics-map` field priorities exactly; corrupt blobs degrade to nulls like the JS `fromJson` policy instead of erroring the scan). `sessionRecordFromProjection` rebuilds `GameSessionRecord`s whose `rawResult`/`difficulty` are minimal shims carrying exactly the fields the shared extractors recognize, so every downstream analytics number is identical to the full-blob path (clamp/mapping still done by the extractors). Runs through the existing public `db.transaction()` adapter seam (pattern already used by cosmetics/rewards/data-portability); JSON1 capability probe memoized; any failure → `null` → caller falls back to legacy full-row reads. Exports: `ProjectedSessionRow`, `PROJECTED_SESSIONS_ALL_SQL`, `PROJECTED_SESSIONS_BY_GAME_SQL`, `DIFFICULTY_LEVEL_PARAMS`, `tryLoadProjectedSessionRows`, `sessionRecordFromProjection`.
- `apps/mobile/src/analytics/queries.ts` (REWRITTEN, exports preserved: `ALL_SESSIONS_LIMIT`, `ProgressSnapshot`, `loadProgressSnapshot(db)`, `loadGameSessions(db, gameId)`) — both loaders now use the projection fast path with legacy fallback; header documents per-query complexity before/after.
- `apps/mobile/src/analytics/__tests__/projections.test.ts` (NEW, 7 pure tests) — pins shim↔extractor parity against the real `metrics-map` functions (score priority, accuracy clamp, reaction mean-over-best, difficulty rating/level mapping, null-blob degradation, scalar passthrough) plus SQL-text determinism guards (json_valid guards, ordering, level bindings).

Design decisions:
- Blob shims instead of dropping blobs: overview/drill-down screens show lifetime accuracy/reaction/score/difficulty from `rawResult`/`difficulty`; nulling blobs would have been a user-visible regression. Shims preserve observable behavior while eliminating ~2 JSON strings + 2 `JSON.parse` per row.
- `ratings.getHistory(ALL)` deliberately left unbounded: rows are already slim (6 scalar cols), and consumers need unbounded evidence (all-time personal bests, all-time trend fallback in progress-domain). Bounding would change visible data; documented as remaining pushdown candidate (needs parent aggregate helper + W08 pure-fn seam).
- Statement count stays constant (≤8 guard in `perf-db-query-patterns.test.ts` unaffected; repo reads unchanged).

Backlog: consumer inventory done (3 snapshot screens + 4 pure aggregators + perf guards freeze the surface); projection/pushdown rewrite done; bounded recent-history specialization evaluated and rejected as behavior-changing (documented above); typed projection module done; complexity table documented in `queries.ts` header.
