## Implementation summary

**Landed:** complete production vertical slice of `attention-sustained-vigilance` ("Signal Watch"), a SART-like go/no-go sustained-attention task, under `apps/mobile/src/games/attention-sustained-vigilance/`.

Files (all new): `game.json`, `game-definition.ts`, `types.ts`, `difficulty.ts`, `generator.ts`, `scoring.ts`, `reducer.ts`, `session.ts`, `hooks.ts`, `screen.tsx`, `versions.ts`, `index.ts`, `components/{button,pause-overlay,qa-panel,tutorial,stimulus-stage}.tsx`, `__tests__/{generator,scoring}.test.ts` (7 tests total, within the ≤8 cap).

**Mechanic + distinctness rationale:** digits 1–9 stream one at a time (fixed slot = stimulusOnMs + isiMs); the player taps GO for every digit except the session's stop digit, which is rare. Distinct from visual-search / odd-one-out (spatial search over many simultaneously visible items — here one stimulus at a time, nothing to search), target-count (numerosity of a flashed grid — no counting), and symbol-tracker (tracking through a scramble — no memory load; the rule is public, the challenge is temporal). It is also the only Attention game where withholding action is the correct answer on target trials (response inhibition + vigilance decrement over time).

**Determinism/generator:** two-phase layout over RNG forks — exact `expectedTargetCount` targets placed via seeded shuffles with a `minTargetGap` constraint (deterministic even-spread fallback, always gap-valid), then a fork-drawn stop digit and per-trial digit draws that exclude it on go trials, so `isTarget ⇔ digit === stopDigit` holds by construction. `validateStream` checks all invariants. Same seed ⇒ identical stream.

**Difficulty:** named mappings easy→expert vary trials (24–42), stimulusOnMs (900→500), isiMs (600→350), responseWindowMs (1400→850), targetRarityPct (17%→8%), minTargetGap (4→7), RT anchors (450/1100→300/800 ms). Adaptive tightens/relaxes the response window ±100 ms within [600, 1400]; neutral start 1000 maps exactly to challengeRating 0.5 via `sessionChallengeRating`. Strict profile decode/validation mirrors number-line conventions.

**Timing:** reducer never reads a clock; `trial-tick`/`respond` carry lifecycle active-ms. Window timeout resolution, slot-end auto-advance (scheduled onset keeps cadence drift-free), and RT capture are pure reducer logic; pause freezes everything; AppState auto-pause wired in screen.tsx.

**Scoring:** hit = 100 + round(50×speedFactor) (speedFactor anchored rtTarget→rtFail); correct hold = 120; omission = 0; commission = −80 with running score floored at 0. Normalizer: `clamp01(0.5·goAccuracy + 0.3·holdAccuracy + 0.2·meanSpeed)` → perfect session = 1.0, all-error = 0. Raw result carries the full reproducibility envelope + diagnostic metadata; persistence via the standard `dbSessionPersister` seam and `completeSession`.

**QA/a11y/sensory:** dev-gated QaPanelShell + force-win/force-lose/force-state behind `assertDevOnly()` (forced sessions flagged); two-step TutorialFrame tutorial with QA skip; all testIDs via `testId(GAME_ID, …)`; sensory via canonical `liveAudioHaptics.feedback('tap'|'correct'|'wrong'|'failure'|'success')` literals; challenge hidden while paused (`importantForAccessibility="no-hide-descendants"` + `accessibilityElementsHidden`) under the shared opaque PauseOverlay; stage announces current digit + public rule without leaking future trials.

**Registry note:** parent must regenerate `src/registry/*` (`node scripts/generate-game-registry.mjs`) at convergence to pick up the new `game.json`; no shared files were touched by this worker.
