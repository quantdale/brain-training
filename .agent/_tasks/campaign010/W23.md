## Implementation summary

All four W03 wave-1 content-depth proposals evaluated; three implemented, one skipped as unsound (rationale below). Every new template/pool was machine-verified (node scripts implementing the exact module semantics) before landing; generators stay deterministic and fork-salted; scoring semantics and reducer behavior untouched; no screen.tsx touched in any module.

**1. `math-fast-math` — expert two-step tier (implemented)**
- `MathProblem` gained optional `secondOperator`/`secondOperand` (additive; expression = `left op right ± c`, left-to-right). Reducer/scoring unchanged — they consume `answer` only.
- New `params.twoStepChance` (expert = 0.35, others absent/0), encoded additively in the difficulty profile (`twoStepChance` key, validated [0,1] on decode; older persisted profiles decode as no-tier, preserving historical reproducibility). Adaptive ramps the chance linearly toward the expert value and omits it while zero, so step-0 params still equal the base exactly.
- Generator: per-problem gate fork (`twostep-gate:problem:<i>`) → curated `TWO_STEP_TEMPLATES` (10 entries, arithmetic + range-verified) → procedural candidates reusing the validated single-op draw plus a `+`/`−` tail bounded by tail-range maxRight, answer ≥ 1 and ≤ 999 (`MAX_TWO_STEP_ANSWER`, keeps the ≤3-digit input invariant). Gate skipped entirely at chance 0, so non-expert seed streams are byte-identical to before. `problemSignature` extends with the tail (single-op signatures unchanged); `isTrivialProblem` guards degenerate tails.
- Minimal render extension inside owned components (NOT a screen rewrite; screen.tsx untouched): `components/problem.tsx` renders the second operator/operand (+2 semantic testIDs `problem-second-op`/`problem-second-operand`), `components/feedback.tsx` includes it in the recap line. Tutorial demo params have no tier → demo unchanged.
- `session.ts` records `twoStepChance` in `generatorInfo` (reproducibility envelope).
- game.json: gameVersion 1.0.0→**1.1.0**, generatorVersion 1.0.0→**1.1.0**.
- Tests updated (owned files): `assertProblemValid` now validates the intermediate + tail; 4 new capped tests (tier active at expert / never below; exactness+bounds over 50 seeds; determinism; signature).

**2. `math-number-line-estimation` — non-zero expert origin (implemented)**
- Expert line switched `[0, 1000]` → **`[250, 750]`** (W03's proposal). Generation/scoring/rendering are fully span-relative (verified: margins, variety distance, tolerance %, snap, endpoint labels all derive from `lineMin/lineMax`), so this is purely a tuning change that forces true interpolation — anchor-relative heuristics ("near 0/near 1000") stop working. Pixel-level tap difficulty is unchanged because tolerance is a fixed percent of span and span maps onto the same widget width.
- game.json: gameVersion 1.0.0→**1.1.0**; generatorVersion stays 1.0.0 (algorithm unchanged; identical `(seed, params)` still reproduce identical rounds; old sessions reproduce via their persisted profiles).
- Test updated: expert `toleranceSpan` expectation 25 → 12.5 (2.5% × 500).

**3. `math-equation-builder` — larger curated bank (implemented)**
- `PUZZLE_TEMPLATES` 25 → **51**: +3 easy 3-number sets (+/− solvable — the only mix that can draw count-3), +13 normal/hard 4-number sets (targets 24–95), and the FIRST 5-number pool (10 sets, targets 60–200) — expert previously had zero curated content because every template had ≠5 numbers.
- All 51 entries machine-verified: solvable via the exact `canSolve` binary-tree semantics under the smallest operator mix of any level that can draw them, globally unique targets, numbers ∈ [2,20] distinct, each serving ≥1 shipped window. Order-sensitive decompositions were caught and fixed by this verification pass.
- **Pre-existing dead content found (not mine, left untouched):** eight 3-number ×-needing templates ([10,3,4]→26, [8,7,3]→53, [6,5,4]→54, [9,4,2]→38, [7,6,3]→45, [10,5,2]→52, [8,6,4]→44, [13,2,5]→31) can never be drawn — easy is the only `numbersCount=3` level and its +/− mix always fails their solvability filter. Parent may prune or remap in a later pass.
- game.json: gameVersion 1.0.1→**1.1.0**, generatorVersion 1.1.0→**1.2.0** (same-seed output changes via template priority).

**4. `math-missing-operator` — depth decision (partial: safe alternative implemented, W03's specific idea skipped)**
- SKIPPED as unsound under packet constraints: squared terms require a 5th operator token (screen buttons + reducer-facing type change) and invalidate the module's exhaustively-proved unique-solution lemma ((2,2)/(4,2) analysis covers {+,−,×,÷} only) without a fresh ambiguity proof; missing-operand variants change what the player answers (mechanic change). Both violate "no reducer behavior/scoring changes".
- Implemented instead the sound curated-depth option: `EQUATION_TEMPLATES` 22 → **34** via a large-operand block (12 entries, ÷ up to 96÷8, × up to 28×5, mixed +/−), each machine-verified to have exactly one correct operator among all four; b ≤ expert maxB(11) so the existing compatibility filter admits exactly the intended levels, and a > 40 entries surface naturally in later expert rounds as aMax escalates to 99.
- game.json: gameVersion 1.0.0→**1.1.0**, generatorVersion 1.0.0→**1.1.0** (template priority changes same-seed draws).
