## Implementation summary

Three pure, dependency-free seams delivered under `apps/mobile/src/` (additive only; nothing wired into screens; no product decisions locked):

**1. `src/entitlements/`** (constitution §23 seam)
- `types.ts`: `EntitlementFeatureKey` (`training` | `cosmetics` | `data-portability` | `ai-assistant`, additive union), `EntitlementSource` (`local-default`/`purchase`/`subscription`/`promo`/`unknown`), `FeatureEntitlement` (granted/source/`remainingUses: number | null` metering), synchronous-by-design `EntitlementProvider` interface with documented plug-in point for a future billing provider (snapshot-based resolve, never throws), `ENTITLEMENTS_SEAM_VERSION = '1.0.0'`.
- `local-provider.ts`: `ALL_FEATURE_KEYS`, `localDefaultEntitlement`, `createLocalDefaultEntitlementProvider()` — everything free/unlocked/unmetered as shipped today.
- `resolve.ts`: `resolveEntitlement`, `resolveEntitlements` (deterministic input order), shared `isUsable` rule (granted AND not exhausted).
- No pricing, tiers, or free-tier limits encoded (deferred decisions untouched).

**2. `src/notifications/`** (constitution §24 seam)
- `types.ts`: `DayOfWeek` (JS `getDay` convention 0=Sun..6=Sat), `MinuteOfDay`, additive `NotificationIntentKind` vocabulary (`streak-reminder` | `workout-reminder`), `ScheduleIntent` (enabled + optional time window in local minutes-of-day + explicit day list; empty days = off, never "every day"), `NotificationPreferences` (master switch + intents), `NOTIFICATIONS_PREFERENCE_FORMAT_VERSION = 1`. Zero expo-notifications usage.
- `defaults.ts`: only the all-off null state (`createEmptyNotificationPreferences`) — explicitly documented as NOT a default schedule; real schedule/copy remain deferred decisions.
- `normalize.ts`: deterministic repair of untrusted input — minute clamping to 0..1439, day-list dedupe/sort, half-specified or midnight-crossing windows reset to undecided (never guessed), unknown future kinds dropped, missing known kinds re-added canonically; `isWindowDecided` / inclusive `windowCoversMinute` helpers.

**3. `src/assistant/`** (constitution §22 seam)
- `types.ts`: structural views mirroring stored rows (`DomainRatingView`, `GameAggregateView`, `RecentSessionView`, `StreakStateView` — plain-string domains so db rows pass without casts), `AssistantContextSummary` DTO with `advisoryOnly: true` as a literal type (write intent cannot compile into the DTO), history transport DTOs (`AssistantExchange`, `AssistantThreadSummary`, roles/statuses) with persistence format left deferred; constants `ASSISTANT_CONTEXT_VERSION`, `STALE_DOMAIN_DAYS = 30` (mirrors personalization staleness convention), `RECENT_SESSION_LIMIT = 10`, `TOP_GAME_LIMIT = 3`.
- `context.ts`: `buildAssistantContextSummary(args)` — pure aggregation with defensive sanitizers (corrupt rows dropped, normalized results clamped to [0,1], XP sanitized then level derived via the shared curve `levelForXp` from `@/rating`), fully specified deterministic ordering (domains weakest-first with name tiebreak; top games count desc → lastCompletedAt desc → gameId asc), capped lists, injectable `nowMs` (omitted → `generatedAtMs: null`, staleness verdicts `null` instead of guessed). No provider, no network.

Tests (small, per contract cap): `__tests__/entitlements.test.ts` (4 cases), `notifications.test.ts` (5), `assistant.test.ts` (4) covering determinism, sanitization, ordering, and the provider plug-in contract.

NEEDS_PARENT: none — everything fit inside owned paths.
