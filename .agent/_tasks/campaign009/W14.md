## Mission — close the full-catalog validation gap
1. **KNOWN DEFECT (fix first):** `scripts/qa/autobot.mjs` hardcodes a stale
   24-game `GAMES` array while the product registry has 36 games. Replace the
   hardcoded list with derivation from the actual catalog — parse
   `apps/mobile/src/registry/registry.generated.ts` or scan
   `apps/mobile/src/games/*/game.json` — so the harness scales automatically
   as the catalog grows. Keep a documented canary subset for quick runs.
2. Improve per-game smoke coverage: launch via deep link; tutorial or QA
   bypass; start; at least one real interaction; pause; resume; QA force-win
   where exposed; results screen; persistence evidence; back navigation;
   next game. Machine-readable failure artifacts (JSON + screenshot +
   hierarchy + logcat slice) per failing game.
3. Never use physical/global host mouse or keyboard — ADB/emulator-local only.
4. The harness must degrade gracefully when no emulator is attached: clear
   `NOT VALIDATED`/`BLOCKED` reporting, never fake PASS. Parent executes the
   emulator run later; your job is to make that run trustworthy and automatic.
5. Update the self-test (`scripts/android/self-test.sh`) if needed for new
   helpers.

## Validation
- `node scripts/qa/autobot.mjs --list-games` must print all 36 ids and pass its
