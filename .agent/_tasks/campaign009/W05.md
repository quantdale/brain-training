# Worker 05 — Game platform + cross-catalog quality

## Owned write surfaces
- `apps/mobile/src/components/game-ui/**`
- `apps/mobile/src/sdk/**` (additive/backward-compatible changes only; breaking
  contract changes must be REPORTED, not made — 36 games depend on these types)

Read everything; edit only the above. Tiny representative fixes inside
individual games are allowed ONLY for call-sites broken by your shared changes,
and each must be listed in your report.

## Mission — audit the complete game platform across all 36 game modules
1. Lifecycle consistency: session start/complete/abandon semantics; timeout
   semantics uniformity; pause/resume contract; QA force-win/force-loss states;
   stable testID conventions (`@/sdk` testid helpers); tutorial lifecycle
   (first-play gating, replay, QA bypass); Adaptive difficulty contract;
   authoritative result handoff to persistence; sensory event vocabulary
   conformance; shared result UI usage; error handling.
2. Find cross-catalog inconsistencies by READING every game module. Prefer
   fixing the shared abstraction over per-game patches where safe.
3. Add regression tests around shared contracts (contract tests that would
   catch a new game violating lifecycle/pause/QA/testID conventions).
4. Do not change gameplay of any individual game.

## Validation

- `npx tsc --noEmit` → only your files may have errors.
