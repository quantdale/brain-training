# Worker 10 — Database + migration integrity (single DB worker)

## Owned write surfaces
- `apps/mobile/src/db/**` — the ONLY worker allowed to touch
  `schema.ts` / `migrate.ts` / migration ordering.

## Mission — audit schema v1→current (v8)
1. Test matrix: fresh install; every supported historical upgrade path;
   repeat initialization (idempotent); interrupted migration recovery;
   transaction rollback on failure; corrupt stored values handled gracefully;
   FK behavior; uniqueness constraints; index usage (add indexes ONLY with
   measured evidence, e.g. EXPLAIN QUERY PLAN on realistic volumes);
   operation_id idempotency for session completion and ledger entries;
   timestamp handling; large histories (thousands of sessions) performance;
   duplicate session completion attempts.
2. Never reset user data as a convenience. New migrations must be additive,
   ordered, and tested from every historical version present in the wild code
   paths.
3. Fix defects with regression tests. Report any schema change clearly in your
   final report (parent reviews before integration).
