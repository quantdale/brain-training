# Worker 06 — Daily workout + personalization

## Owned write surfaces
- `apps/mobile/src/workout/**`

Read-only dependencies: `src/db/workout.ts`, `src/registry`, `src/app/(tabs)/index.tsx`,
`src/app/results.tsx`. If these need changes, report precisely — do not edit.

## Mission — harden the complete workout lifecycle
1. Lifecycle: selection → persistence → resume → launch → completion → advance
   → final completion → reroll economics → date rollover → app restart →
   partial completion. Add tests for each transition, including kill/relaunch
   mid-workout and idempotent advance.
2. Catalog growth: selection must behave correctly as the catalog grows from
   36 toward ~40 games (no hardcoded ids/count assumptions). Simulate growth
   in tests.
3. Invalid game ids in a stored instance (e.g. game removed later): graceful
   reconciliation, no crash.
4. Personalization via authoritative history only: weak-domain targeting,
   staleness, recent-game avoidance, variety, category balance, difficulty fit,
   new-player behavior (empty history), determinism/explainability. No opaque
   scoring magic — every choice must be testable and explainable.
5. Reroll attempts persistence and economy interaction stay correct.
