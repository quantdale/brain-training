## Failure findings (classified)

1. **HIGH — Reroll after partial completion silently drops freshly-selected games** (`src/workout/use-workout.ts` ↔ `src/db/workout.ts applyReroll`).
   Symptom: after completing k≥1 games, `reroll()` handed `applyReroll` a fresh-only id list while the repository API is POSITION-based (`newGameIds.slice(currentIndex)`), so exactly the first k games of every fresh reroll selection were sliced off and lost; the persisted tail diverged from the deterministic seeded selection (provenance violation).
   Root cause: caller/repository contract mismatch introduced when the hook switched to exclude-based selection; pre-existing tests passed full-length lists so neither side caught it.
   Fix: hook now feeds the positional form (played prefix as placeholders + fresh selection truncated to remaining slots); repository doc corrected to state the positional convention. Evidence: `reroll-partial.test.ts` failed before the fix ([f2,f3,f4] persisted vs [f1,f2,f3] expected), passes after; lifecycle + 006R repo suites unchanged/green.

2. **MEDIUM — `listHistory`/`listRecent` ordering contradicted the documented contract** (`src/db/workout.ts`).
   Symptom: doc comments (and campaign-010 W22's documented decision) promise daily-row-before-template-rows within a day; `ORDER BY date DESC` actually returned template rows FIRST within a day (namespaced keys sort after the bare date).
   Fix: two-key sort `ORDER BY substr(date,1,10) DESC, date ASC`. Pinned in `workout-v2.test.ts` (ordering suite).

3. **MEDIUM — Persisted generation inputs never survived a db read** (`src/workout/metadata.ts parseWorkoutMetadata`).
   Symptom: valid `inputs` snapshots were discarded on read, breaking the documented "re-running the recorded inputs reproduces the selection" provenance guarantee.
   Fix: validated round-trip, all-or-nothing (any malformed entry drops the whole snapshot rather than masquerading as valid). Pinned in `metadata.test.ts` + metadata-column round-trip test.

4. **LOW — Duplicate game ids in a stored row survived reconciliation** (`src/workout/reconcile.ts`).
   Symptom: a drifted row with `[dup-a, b, dup-a]` stayed duplicated → completion summaries could double-count XP/sessions.
   Fix: first-occurrence dedupe inside `reconcileWorkout`. Pinned in `workout-v2.test.ts`.

5. **LOW — `buildWorkoutSummary` crashed with TypeError when called without the sessions argument** (`src/workout/summary.ts`).
   Symptom: `sessions` param had no default while later params did; direct callers omitting it got `TypeError: sessions is not iterable`.
   Fix: default `[]`; pinned.

Attacked with no defect found (evidence = passing tests): double/repeat advance calls at repo level (clamped, terminal-stable) and guard-level exactly-once (`advance.test.ts`, lifecycle); corrupt `game_ids_json`/`metadata_json`; negative/overflow/fractional `current_index` (summary clamp + reconcile repair + persist); zero eligible games & empty-catalog templates; insufficient focus pool top-up (no duplicates, ≤6 distinct); unknown-key advance/reroll throws; completed-instance reroll refusal; countCompleted template exclusion; session↔position matching incl. most-recent-since-creation, pre-creation exclusion, cross-instance shared sessions; leap-day/midpoint date math (`nextDate`/`previousDate`/`dayIndexFromBase('2028-02-29')=789`); 7-day injected-clock rotation sweep (determinism, consecutive-day distinctness, cycle wrap, pre-base wrap, skip menus); paidReroll in-transaction balance guard; legacy rows without metadata load fine.
