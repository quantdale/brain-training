## DISTINCTNESS REVIEW (§9 verdict)

Order Sweep is **trivially distinct from `speed-quick-compare`**: quick-compare is a one-shot-per-round binary/ternary judgment — a single `answer` selecting the option that satisfies one comparison (`correctIndex`, then immediate feedback; timeout = miss). There is no sequencing, no repeated minimum-selection, no scan-among-many; Order Sweep demands an ordered multi-tap sweep of 6–16 visible tokens against a draining window. Different task family (decision vs serial ordering).

Against `math-value-ordering` the overlap is real but not disqualifying — both reduce at the abstract level to serial minimum-extraction over pairwise-distinct values displayed simultaneously in shuffled positions (value-ordering's `minimumRemainingTile` loop + shuffled tile order; Order Sweep's ascending `order[]` + shuffled cell deal). Four material differences keep Order Sweep a separate mechanic: **(1) Cognitive disguise** — value-ordering hides values behind arithmetic expressions (`a + b`, `a − b`, `a × b`, ranges up to 1..1000), so its load is arithmetic-decoding + ordering; Order Sweep shows plain integers sampled from a range much wider than the token count (9 tokens from 1..40; 16 from 1..90), so its load is pure visual scan/search among many distractors — the cancellation-task demand, with no arithmetic. **(2) Scale** — 3–6 expression tiles vs 6–16 grid tokens (expert is a 4×4 board with holes-free layout derived from count/columns). **(3) Error model** — value-ordering resolves the round immediately as `mistake` on any wrong tap (fail-fast, score only perfect rounds); Order Sweep forgives mistakes (counts them, breaks the streak, round survives) and scores every correctly swept token. **(4) Timing/adaptation architecture** — value-ordering drives reducer-resolved lifecycle active-time ticks and adapts tile count; Order Sweep uses screen-stamped monotonic deadlines with pause-shift anchor arithmetic and adapts the window duration inside [4000, 10000] ms.

**Verdict: MATERIALLY DISTINCT.** The shared skeleton (ascending order over distinct values) is a genre, not a duplicate; Order Sweep owns the "wide-range plain-number visual scan under time pressure with mistake tolerance" quadrant, which nothing else in the catalog covers. No mechanic refinement required. Recommendation (non-blocking): keep catalog copy emphasizing *scan among many numbers, mistakes allowed, beat the clock* so store/tutorial positioning never collides with value-ordering's *decode expressions, perfect-or-fail* framing.
