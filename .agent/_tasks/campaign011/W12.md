### Failure findings (classified)

1. **CRITICAL — single-pass serializer hashed wrong bytes; every fresh export rejected on import.**
   - Files: `src/data-portability/serialize.ts` (`serializeEnvelopeWithChecksum`); symptom surfaced via `deserialize.ts:453` in all 6 failing suites (23 tests).
   - Root cause: W10's one-pass writer inserted `checksum` into sorted top-level keys but hashed the structural commas ADJACENT to it. Digest must equal `computeChecksum(canonicalString(payload))` (payload = envelope WITHOUT `checksum`), so those commas must not be hashed. Two byte-level variants, both proven by candidate-digest matching BEFORE the fix: with `appVersion` present → doubled comma (`…"test-1.0.0",,"checksumAlgorithm"…`); without `appVersion` (checksum sorts FIRST) → leading comma (`{,…`). Result: embedded digest never matched the recomputed digest ⇒ ChecksumMismatchError on 100% of exports; export→import fully broken.
   - Fix: output commas and hashed commas tracked separately (`hashedMembers` counter) — every boundary after the first gets an output comma; only commas between two PAYLOAD members are hashed; when checksum sorts first its trailing comma is emitted text-only. During the fix, a second bug (missing comma AFTER a leading checksum → unparseable JSON output) was caught by the new byte-equality assertion and corrected before landing.
   - Pinned: `__tests__/serializer.test.ts` (5 tests): digest ≡ legacy payload hash in BOTH sort positions; output text ≡ `canonicalString({...payload, checksum})`; real bundle/export texts parse; determinism.

2. **HIGH — mid-DDL failure permanently stripped append-only triggers.**
   - Files: `triggers.ts` (`clearTablesIgnoringTriggers`, `recreateTriggers`), `apply.ts` (`applyImport` replace branch), `preview.ts`.
   - Root cause: `dropTriggers()` ran OUTSIDE every try/finally. 11 trigger DDL statements run per clear/replace; a fault among them skipped recreation entirely, leaving the connection without append-only guards — and a later `captureTriggers()` would capture fewer triggers, making the loss PERSISTENT across operations.
   - Fix: drop moved inside the guarded region at all three call sites; `recreateTriggers` now prefixes each create with `DROP TRIGGER IF EXISTS "<name>"` so a partially-dropped state cannot mask the original error with "already exists".
   - Pinned: `__tests__/rollback.test.ts` wipe test faults at exec #6 (mid-trigger-DDL) and asserts the whole-DB dump is byte-identical afterwards (data + trigger DDL).

3. **LOW — large-backup chunk granularity observation (no action under freeze).**
   - The single-pass writer emits ~token-sized chunks: 20k-session export produced 3,520,167 chunks for 15,228,501 bytes (~4.3 chars/chunk). Per-string overhead makes the chunks array itself a meaningful heap consumer during export (see measurement below). Bounded and correct as-is; batching chunks into larger blocks is a possible future optimization, not a defect.

4. **Test-harness notes (not product defects).** Fault injection must be ONE-SHOT (latched): an always-on mutation counter otherwise destroys the very recovery path under test (the trigger recreation inside `finally`). Mocked expo `File(parentString, name)` must join parent+name — a collapsed URI silently redirected writes onto the directory.
