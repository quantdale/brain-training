## Failure findings (classified)

### F1 — CRITICAL (production) — grid-nav PauseOverlay reachability ROOT CAUSE
- File (pre-fix): `src/components/a11y/focus.ts:37`
- Symptom (device): TalkBack never parks on Resume when PauseOverlay opens; users land
  behind the modal with no reachable controls (campaign 009 spatial-grid-nav finding).
- Root cause: `AccessibilityInfo.setAccessibilityFocus(target.current as unknown as number)`
  passed the ref's HostInstance OBJECT where RN 0.86's deprecated legacy API requires a
  NUMERIC reactTag. Verified against installed RN 0.86 source:
  `setAccessibilityFocus(reactTag: number)` → `legacySendAccessibilityEvent.android.js`
  forwards the argument into `UIManager.sendAccessibilityEvent(<object>, typeViewFocused)`,
  which silently no-ops under Fabric. The `as unknown as number` cast suppressed the type
  error that would have flagged this. Reproduced at render level (pre-fix code called the
  legacy API with an object; pinned test now fails on that shape).
- Fix: switched to RN 0.86's modern renderer-routed API
  `AccessibilityInfo.sendAccessibilityEvent(handle, 'focus')` which takes the host instance
  straight from the ref and works on Fabric + Paper, Android + iOS. Retry loop unchanged.
- Evidence: `focus.test.tsx` + `pause-overlay.a11y.test.tsx` (below). uiautomator
  confirmation is W16's per packet.

### F2 — HIGH (production) — A11yDialog re-announces title on every parent render
- File (pre-fix): `src/components/a11y/dialog.tsx` effect keyed
  `[visible, title, announceOnShow, onRequestClose]`.
- Symptom: callers universally pass fresh inline `onRequestClose={() => …}` closures each
  render; any parent re-render while the dialog was open (gameplay ticks, timers)
  re-fired `announce(title)` AND churned the BackHandler subscription (remove/re-add race).
- Fix: split effects. Announcement effect keys `[visible]` only and reads latest
  `title`/`announceOnShow` through refs (fires exactly once per open); BackHandler effect
  keys `[visible, onRequestClose]` (resubscribe churn is inert, no user-visible effect).
- Evidence: `dialog.a11y.test.tsx` "does not re-announce when the parent re-renders with
  fresh inline closures" — fails pre-fix (3 calls), passes post-fix (1 call).

### F3 — LOW (production) — announce() forwarded whitespace-only messages
- File: `src/components/a11y/announcements.tsx`. Guard was `if (!message)`; `"   "` reached
  `announceForAccessibility` (empty/silent utterance on some engines).
- Fix: trim-guard drops blank messages and normalizes padded input.
- Caught by new test before it ever landed green — triaged as production defect (guard
  intent was clearly to drop empty copy), fixed in production, not in test.

### F4 — MEDIUM (documented, not fixed) — A11yDialog focus restore on dismiss missing
- Audit-matrix item "focus restore on dismiss" is not implemented anywhere. Correct
  restore requires a caller-owned trigger ref (the element that opened the dialog lives in
  the caller's tree, not in owned paths). Under feature freeze this is a cross-cutting API
  decision → documented recommendation instead of speculative prop: callers should call
  `requestAccessibilityFocus(triggerRef)` after close where the pattern matters. Practical
  impact today is limited because `accessibilityViewIsModal` subtree removal resets the SR
  cursor to screen top on both platforms.

### F5 — INFO — RNTL v14 query gotchas discovered (affects future test authorship)
- v14's default `getByTestId` matcher skips childless host-leaf Pressables (the scrim);
  Pressables WITH text children match fine. Worked around structurally
  (`.children[0] as TestInstance`) AND gave the scrim Pressable its own stable semantic
  testID (`${testID}-scrim-dismiss`) per constitution §29 QA instrumentation — also
  usable by W16's uiautomator pass.
- Confirmed existing repo note: global RNTL screen singleton leaks interactive state
  across tests within one file; followed the established convention (result-row file
  comment) of isolating stateful QaPanelShell queries into their own file.
- react-test-renderer does not clear external refs synchronously on unmount; ref-lifecycle
  tests must simulate detachment at the seam the code reads.
