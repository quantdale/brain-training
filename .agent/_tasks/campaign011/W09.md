## Failure findings (classified)

- **F1 [Medium] `buildSessionVolume` previous-window boundary double-count** (`volume-view.ts`). Symptom: session at exactly `now−2w` counted in previous window; baseline suite failed (`Expected: 1, Received: 2`). Root cause: inclusive lower bound `[prevStart, start)` contradicted the intended "preceding equal-length window" semantics. Resolution: decided + documented **age-space half-open convention**: headline windows `[start, now]`; preceding window `(now−2w, now-w)` (shared edge at `now−w` belongs to current; outer edge at exactly `now−2w` belongs to older history); weekly tiles age bands `[7k, 7(k+1))`. Note: literal timestamp brackets `[now-2w, now-w)` are mathematically incompatible with the kept test; the age-band reading is what satisfies it with no double-counting. Pinned by exact-edge regressions at `now`, `now±1ms`, `now−w`, `now−w−1ms`, `now−2w±1ms`.
- **F2 [Medium] `buildWeeklyBalance` slice orphan at `t === now`** (`training-balance.ts`). Slices were `[end−7d, end)`: a session completed at exactly `nowMs` counted toward the balance headline but appeared in NO weekly slice (Σslices < headline). Fixed to right-edge-owned tiles `(end−7d, end]`; sum invariant pinned.
- **F3 [Medium] `ActivityCalendar.totalSessions`/`avgPerActiveDay` mixed denominators** (`activity-calendar.ts`). Returned full-history `sessions.length` while cells cover only the grid; screens pass the unbounded snapshot and label the stat "sessions in this view" (`progress.tsx:488`, `progress-domain.tsx:427`, `progress-activity.tsx:105`) — a no-fabrication violation (e.g. years of history → avg 40+ sessions/active-day over a 182-day grid). Fixed: totals derived from grid cells only; regression-pinned with out-of-grid + future rows.
- **F4 [Low/Medium] Future-dated rows counted by window filters** (`windows.ts`, `volume-view.ts 'all'` branch). `filterByWindow`/`filterHistoryByWindow`/`isWithinWindow` had no upper clamp, so import artifacts/clock-skew rows (`completedAt > now`) produced phantom in-window activity, inconsistent with `buildSessionVolume`/`compareRates`. Added `t <= nowMs` clamp everywhere incl. volume's `'all'` branch.
- **F5 [Low/Medium] `compareRates` lifetime rate included corrupt future rows** (`rolling-windows.ts`). Found by the imported-history fixture class (0.02028/wk vs true 0.01738/wk). Fixed: lifetime span/count computed over `completedAt <= now` only.
- **F6 [Medium] PB chain order-dependent across duplicate timestamps** (`personal-best.ts`). With tied `completedAt` (batch imports), the chain depended on row read order, contradicting the module's own "deterministic regardless of input order" doc claim. Fixed: equal-timestamp groups collapse to that instant's max (first row wins exact `(t,value)` duplicates); order-invariance pinned via shuffled-input equivalence across all fixture classes.
- **F7 [Low] `daysSinceLastSession` returned negative staleness for corrupt future rows** (`activity-calendar.ts`, e.g. −3 for a row dated tomorrow). Fixed: future rows ignored (consistent with F4 clamp family), result floored at 0; null when nothing real remains.
- **F8 [Info, not a defect] Statistical note:** 20k uniform draws yield ~H_n ≈ ln(20000)+γ ≈ 10.5 personal-best events; a small chain at scale is correct behavior (asserted via chain properties, not event counts).
