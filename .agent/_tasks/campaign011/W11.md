### Failure findings

1. **HIGH — production — rating history projection dropped fields** (`src/db/rating.ts`). Wave-1 refactor aliased `HISTORY_COLUMNS` to camelCase (`session_id AS sessionId`, `rating_after AS ratingAfter`, `created_at AS createdAt`) while `mapHistoryRow` still read snake_case keys → `getHistory` / `getHistoryWindowed` / `getHistoryForSession` returned `undefined` for `sessionId`, `ratingAfter`, `createdAt` on EVERY row. Real consumers (`analytics/domain-insights.ts`, progress screens) silently received undefined values. Baseline failing test `rating.test.ts "clamps ratings at MIN_RATING"` was one visible symptom (`ratingAfter: undefined`). Packet's suspected root cause ("dropped from projection") was close but the actual mechanism was alias/mapper double-translation.
2. **HIGH — production — progress-projection SQL failed at PREPARE, always** (`src/db/sessions.ts` `coalescedJsonNumbers`). Single-path candidate list (`mDifficultyRating` ← `["$.challengeRating"]`) emitted one-argument `COALESCE(x)` → SQLite rejects at statement prepare → `listProgressProjection` / `listProgressProjectionByGame` threw unconditionally; `tryLoadProjectedSessionRows` caught it and fell through BOTH SQL tiers (they share the same constants) to legacy full-row reads. Campaign 010's W22 fast path never worked anywhere. Visible as 6 red tests in `analytics/__tests__/projections-differential.test.ts` at baseline.
3. **HIGH — production — invalid JSON paths in projection SQL** (`src/db/sessions.ts` `jsonNumberExpr`). Field candidates are bare key names (`"score"`, `"avgResponseMs"`) but were interpolated as JSON paths without the required `$.` prefix → runtime `SqliteError: bad JSON path: 'score'` whenever a row had VALID json blobs (masked until finding 2 was fixed). Fixed by normalizing non-`$` candidates to `$.<field>`.
4. **MEDIUM — wrong test (W09-owned file)** — `analytics/__tests__/projections-differential.test.ts:494` asserts against an alphabetically mis-sorted literal (`"seed"` listed before `"scoringVersion"`, but `.sort()` orders `scoringVersion < seed`). Could never pass once the SQL worked; produces the 3 remaining reds (@1000/@5000/@20000 share one helper). Production shape is correct (`SessionProgressRow` includes `seed`). See NEEDS_PARENT.
5. **MEDIUM — hardening gap — corrupt `user_version` silently replayed migrations** (`src/db/migrate.ts`). A negative/corrupt header value passed the `current > target` guard and re-ran the ENTIRE migration chain (CREATE IF NOT EXISTS + v8 backfill UPDATE) over live data instead of refusing startup. Fixed: negative/non-integer version now rejected with a `/corrupt/` error.
6. **LOW — observed transient, no action** — during one sweep run, `quests.test.ts "records monotonic progress…"` failed because worker W13 was mid-edit across `quests.test.ts`/`quests.ts`; re-run after their edit settled: green (5/5). Not a defect in my surface.
